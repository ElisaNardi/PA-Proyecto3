# PA-Proyecto3 - consigna
Proyecto 3 Desarrollo de un MVP de entrenamiento físico
Borrador

Situación
Una persona, un personal trainer o un gimnasio necesita contar con un sistema que le permita organizar y realizar
el seguimiento de la actividad física y del entrenamiento.
Se propone desarrollar un MVP que permita gestionar y acompañar el entrenamiento, contemplando información
relevante como las rutinas, los ejercicios, las cargas, las repeticiones y la evolución del entrenamiento.
El objetivo no es construir un sistema completo de gestión de gimnasios, sino resolver de manera concreta y
significativa el problema del entrenamiento y su seguimiento.

Alcance
El sistema podrá contemplar las necesidades que el equipo considere pertinentes para resolver el problema
planteado. Como límite explícito, el MVP no deberá incluir:
• gestión de cuotas o pagos;
• turnos o reservas;
• facturación;
• administración comercial del gimnasio.
Fuera de estas restricciones, el problema no define de antemano cómo debe modelarse ni qué funcionalidades
concretas debe tener el sistema. Será responsabilidad del equipo determinar qué necesita el MVP, qué conceptos
forman parte del dominio, qué decisiones de diseño resultan necesarias y cómo llevarlas a una solución
implementable.

Ingeniería de Software
El desarrollo deberá evidenciar la aplicación de los conceptos, principios, técnicas y prácticas de Ingeniería de
Software trabajados durante la materia.
No se establece una lista cerrada de artefactos que deban producirse. El equipo deberá determinar qué
herramientas y prácticas resultan pertinentes para este problema, utilizarlas cuando aporten valor y justificar las
decisiones tomadas. La evaluación no estará centrada en la cantidad de documentos, diagramas o técnicas
utilizadas, sino en la capacidad del equipo para:
• comprender y modelar el problema;
• tomar decisiones de ingeniería;
• justificar esas decisiones;
• construir una solución coherente con el problema;
• anticipar y gestionar cambios e incertidumbres;
• comunicar y fundamentar el trabajo realizado.
El equipo deberá poder explicar por qué hizo lo que hizo, qué alternativas consideró y qué consecuencias tienen
sus decisiones.

Consultas, borradores y entregas
Durante el desarrollo del proyecto se podrán realizar consultas y presentar borradores para recibir orientación y
retroalimentación.
Hasta el 14 de noviembre de 2026 inclusive, las consultas, avances y borradores enviados tendrán carácter de
instancia de trabajo y no serán considerados entregas formales.
A partir del 15 de noviembre de 2026 inclusive, todo material enviado al equipo docente será considerado una
entrega del proyecto. Esto incluye, entre otras posibilidades:
• una versión del proyecto;
• un documento o parte del análisis;
• un borrador;
• una consulta acompañada de material para revisión;
• una pregunta cuya respuesta requiera revisar o evaluar una parte del proyecto;
• cualquier otro material presentado para recibir una revisión del trabajo realizado.
Desde esa fecha, cada equipo dispondrá de hasta dos entregas para revisión antes de la instancia de evaluación.
Por lo tanto, se recomienda utilizar las instancias previas al 15 de noviembre para realizar consultas, discutir
decisiones, presentar avances y recibir retroalimentación.

Fecha máxima de entrega
La fecha máxima para la entrega definitiva del TP3 será el último turno de examen correspondiente al período de
diciembre de 2026.
No se considerarán entregas posteriores a dicha fecha.

Una condición fundamental
El sistema no debe ser entendido únicamente como un conjunto de funcionalidades implementadas.
El proyecto deberá permitir observar cómo el equipo hizo Ingeniería de Software para llegar a esa solución.
El equipo deberá estar en condiciones de explicar y fundamentar las decisiones tomadas durante el desarrollo.
